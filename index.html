Производство → iiko

Получить план производства с MAIN

Без входа в аккаунт. MAIN передаёт Excel только по запросу. Уже готовый Excel загружается через основной сервер напрямую в браузер, без ожидания MAIN и без временных ссылок. Если основной канал недоступен, пробуем резервный сервер и защищённое хранилище. Готовый файл повторно используется в рамках открытого сеанса; новые задания и отправка в iiko автоматически не повторяются. После скачивания обрабатывается лишь вкладка выбранной даты, а не вся книга. В iiko пока ничего не создаётся.

Для подключения нужен код с компьютера MAIN.

После подключения код сохранится в этом браузере и будет восстановлен при следующем открытии.

Акты приготовления за выбранную дату

Выберите дату. «Помогатор» найдёт соответствующую вкладку в Excel (дату также можно выбрать прямо из списка листов), найдёт столбец «iiko» и возьмёт количества только из него для двух актов: до компотов включительно — БК, выпечка — ПК. Для больших пирогов количество из столбца iiko переводится в куски: 1 пирог = 8 кусков. Обычные пирожки не пересчитываются. Без проведения и без отправки в iiko.

Выберите дату, затем нажмите «Получить план с MAIN» выше либо загрузите Excel ниже.

Это предварительный просмотр. Пробная отправка доступна ниже, в блоке iiko, после сверки и подтверждения.

Выгрузка актов приготовления в iiko

Сопоставление: сравниваем начало названия блюда до первой скобки с iiko. Состав в скобках не учитываем. Для несовпавших блюд администратор выбирает нужную позицию iiko, подтверждает и сохраняет соответствие на сервере для всех, кто подключён к этому MAIN. В исходном плане названия менять не нужно. Теперь можно отправлять по одному акту в iiko со статусом NEW (без проведения), только после проверки и подтверждения.

Подключение к действующему iikoServer. Пароль хранится на сервере и не передаётся в браузер.

Отдельная авторизация не нужна — ни аккаунт, ни гостевой вход Supabase. Доступ к iiko подтверждается сохранённым 32-символьным кодом MAIN. Акты отправляются только вручную, после подтверждения, со статусом NEW без проведения.

Получите новый файл с MAIN или загрузите отдельный Excel для перемещений.

Шаг 2. Проверка перемещений

После получения Excel перемещения формируются автоматически: блюда до последнего компота включительно, затем раздел «Допы» исключается, после него отдельно обрабатывается выпечка. Пироги 1000 г переводятся в куски ×8. Все перемещения можно отправлять в любом порядке, в том числе одновременно; после подтверждения отправки каждой кнопка блокируется.

После формирования перемещений сразу появится общий блок сопоставления: найденные совпадения, позиции для ручного подбора и все запомненные соответствия MAIN. Поиск и кнопка «Подтвердить и запомнить» общие с актами приготовления. Отправка в iiko только вручную после проверки.

Показать алгоритм перемещений

Алгоритм создания перемещений

Для перемещений загружается отдельный, обновлённый Excel после утреннего плана приготовления. Утренний Excel и готовые акты не изменяются. Это предварительная проверка, без отправки и проведения в iiko.

  1. Новый Excel. Во второй половине дня получаем с MAIN отдельную сохранённую версию плана (обычно около 16:00). Утренний план приготовления не меняется.
  2. Точки из плана. Раздача Правды (ПР), Бестужевская, Модуль, ЭТМ, Рэдмонд. МЕГА и Мед экспресс исключены из списка получателей и документов перемещения. ЭТМ ДЕНЬ + ЭТМ НОЧЬ = одна точка ЭТМ и один документ. Для БР создаём только перемещение выпечки БК → БР.
  3. Вся выпечка, кроме ПР. Для каждой позиции берём количество из графы «Всего» в блоке выпечки и вычитаем только количество из графы «Раздача Правды». Формируем Правда кухня → Бухара кухня. В эту сумму входит выпечка для БР, внешних заказчиков и остальных точек. Затем создаём БК → БР только по выпечке и БК → другие точки по их колонкам.
  4. Выпечка ПР. Полностью исключается из перемещений. Документ ПК → ПР не создаётся. Выпечка ПР не включается и в БК → ПР.
  5. Остальные блюда. Из колонки конкретной точки формируем Бухара кухня → точка, включая обычные блюда для ПР. Остальные блюда для БР исключаем — в БК → БР остаётся только выпечка.
  6. Количество. Для распределения БК → точки берём колонку получателя; ЭТМ день и ночь складываем. Для БК → БР берём выпечку из колонки БР. Для ПК → БК используем «Всего» из раздела выпечки минус ПР (не столбец iiko). Состав в скобках игнорируется при будущем сопоставлении.
  7. Контроль. Основную строку заголовков используем для точек, отдельную строку заголовков выпечки — для «Всего» и «Раздача Правды». Проверяем некорректные количества, повторяющиеся позиции и строки без кода. Строки без кода оставляем в черновике с предупреждением.
  8. iiko. Документы отправляются в iiko вручную, по отдельной кнопке каждого перемещения, со статусом NEW (без проведения). Автоматической отправки нет, очередность документов свободная. Кнопка блокируется сразу при запуске передачи перемещения, независимо от ответа iiko. При подтверждённом результате отображается «Отправлено»; если ответ не подтверждён — «Отправка запущена». Повторная отправка и проверка журнала iiko из Помогатора отключены.

Для больших пирогов (от 900 г) количество умножается на 8 и в актах приготовления, и во всех маршрутах перемещений. Небольшие пирожки не пересчитываются. Выгрузка перемещений независима от очередности; кнопка блокируется при начале отправки и не разблокируется автоматически.

Печатные формы перемещений

Номер, блюдо, количество, цена и сумма. Отдельная форма для каждого маршрута.

Расходные накладные покупателям

Данные из выбранного листа плана. Гранд Капитал и Гранд Капитал ночь объединяются. Предпросмотр без отправки в iiko.
