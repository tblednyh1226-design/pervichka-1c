# Подготовка актов приготовления из Помогатора для iikoServer

## Уже реализовано
- Источник: Excel с MAIN или локальная загрузка, дата выбирается пользователем.
- Два акта за день: Бухара кухня (BK) и Правда кухня (PK).
- Статус актов `NEW` — без проведения. Никакой автоматической отправки.
- Номера стабильны для одной даты: `POM-YYYYMMDD-BK`, `POM-YYYYMMDD-PK`.
- Импорт каталога iiko из XLSX с наименованием и UUID либо артикулом.
- Импорт ранее созданной таблицы соответствий; варианты «Проверить» и «Не подтверждено» блокируют пакет.
- Неоднозначные каталожные имена, отсутствующие позиции, пустые склады, повторяющиеся товары разных объёмов блокируют пакет.
- Скачивание ZIP: манифест JSON и два XML документа.

## Подключение к настоящему iikoServer (НЕ включено)

Подтверждённый путь для iikoServer API: `POST /resto/api/documents/import/productionDocument`; тело XML с корневым `document`, полями `status=NEW`, `documentNumber`, `dateIncoming`, `storeFrom`, `storeTo`, `items/item/amount`, `product` или `productArticle`. До запуска сверить DTO с установленной версией iiko.

Не передавайте токен, пароль iiko или системный ключ интеграции в GitHub Pages, localStorage или URL.

Перед включением «Отправить в iiko» необходимо:
1. Разместить защищённый API-адаптер на сервере, где доступны учетные данные iiko; проверять авторизацию владельца на сервере.
2. Проверить что выбранные склады iiko существуют, и что номенклатура сопоставлена по ID/артикулу, а не только по похожему названию.
3. В транзакционном реестре на сервере зарезервировать уникальный ключ (дата, точка, тип документа). Запретить повторное создание при уже отправленном / неизвестном статусе.
4. До импортирования проверить в самом iiko наличие такого номера документа; при найденном документе сравнить строки и не создавать дубль.
5. Сначала провести dry-run в отдельной тестовой среде; только после этого разрешить оператору отправку на реальный сервер. Отправлять исключительно `NEW`, не `PROCESSED`.
6. Проверить подтверждение сервера: HTTP 200 не гарантирует принятие; проверять `<valid>true</valid>` и фактическое появление акта.
7. Хранить журнал ошибок и идентификаторы документов в серверной базе.

Тестовый ZIP **не отправляет документы в iiko** и может быть проверен локально.
