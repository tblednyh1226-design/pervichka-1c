# Подключение 1С:УНФ Общепит «Колхоз» к Помогатору

## Что уже настроено
- В Помогаторе есть раздел «1С Колхоз · API»: \`unf-integration.html\`.
- В Supabase проекта \`dwdunpyzcfdwokoczenl\` работает Edge Function \`unf-odata-readonly\`.
- Пока разрешены только запросы \`status\`, \`probe\`, \`sample\`. Ни один из них не меняет данные 1С.
- Подключение требует авторизации владельца/администратора рабочего пространства.

## Проверка на сервере 1С

1. Уточните версию конфигурации УНФ/Общепит и платформы (меню «О программе»).
2. Уточните, опубликована ли база через IIS / Apache.
3. В Конфигураторе 1С: «Администрирование» → «Публикация на веб-сервере», включите стандартный интерфейс OData. Настройте состав публикуемых объектов и права отдельного пользователя 1С с доступом ТОЛЬКО на чтение.
4. Локально на сервере проверьте адрес вида \`http://localhost/ИМЯ_ПУБЛИКАЦИИ/odata/standard.odata/\`, затем \`.../$metadata\`. Проверять тестовыми учётными данными API-пользователя.
5. Для облачного сервера нужен HTTPS с доверенным сертификатом и сетевое ограничение доступа. Не публикуйте OData наружу без защиты. При отсутствии защищённого внешнего адреса следует использовать исходящий агент на сервере 1С.
6. Только при защищённой HTTPS-публикации задайте в секретах Supabase проекта:
   - \`UNF_ODATA_URL\` — полный URL, заканчивается на \`/odata/standard.odata/\`.
   - \`UNF_ODATA_USERNAME\` — логин отдельного API-пользователя 1С (желательно латиницей).
   - \`UNF_ODATA_PASSWORD\` — пароль отдельного API-пользователя.
   
   В GitHub, коде браузера или чате эти реквизиты **не сохранять**.

7. Откройте \`unf-integration.html\`, войдите в свой аккаунт, нажмите «Проверить настройки», затем «Проверить соединение с 1С».

## Сводный выпуск (следующий этап)
До реализации нужно выяснить реальные имена OData-сущностей:
- Документ расходной накладной и табличная часть проданной номенклатуры.
- Документ «Выпуск блюд», склады и механизм расчёта по рецептурам.
- Взаимосвязь реализованной продукции с выпуском и защита от повторного включения накладной.
- Изготовленное сверх продаж и возможность отражения остатков.

План: дата + склад → выбор расходных накладных → агрегирование одинаковых блюд → предварительный просмотр и проверка рецептур → создание **одного непроведённого выпуска** через специализированный HTTP-сервис расширения 1С (если OData не выполняет штатные процедуры заполнения). До согласования этого этапа запись в 1С запрещена.
